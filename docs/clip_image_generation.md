# Experimental MEG-to-image workflow

1. Select **CLIP image generation (image-specific ridge, experimental)** or **CLIP image generation (two-stage hybrid, experimental)** in the concept decoder menu.
2. Select source parcels and preprocessing as usual. This mode uses a random split of image identities within each concept and requires a positive validation percentage. **Avg trials** averages only repeated presentations of the same image, within its assigned partition. At least three distinct images per concept are required. Target SVD dimensionality reduction can be configured using **Target SVD** (e.g. 16, 32, or 40 components; 0/Full for 768-D targets). Epochs, early stopping, and embedding dictionary do not apply.
3. Press **Train / test decoder**, then select the folder containing stimulus images. Filenames must match the trial table. This version expects a flat image folder.
4. Training automatically saves a model bundle, predictions, settings and compatibility profile in a timestamped `clip_generation_*` folder under the concept output directory.
5. Press **Generate image…**, enter a zero-based held-out average index from the Predictions table, and wait for the local background process. The preview shows one contributing stimulus, generation from the exact stimulus image embedding (an oracle reference, not a brain prediction), generation from the MEG-predicted vector, and generation from the MEG prediction after subtracting its block concept vector. Images and exact vectors are saved automatically beside the model.

The feature uses the pinned Lambda image-variation generator's ViT-L/14 raw projected 768-dimensional vectors. Each trial targets its individual stimulus image embedding. The frozen image encoder processes all stimulus files: training images provide regression targets, validation images select ridge alpha (and hybrid residual weight beta), and test images supply evaluation targets and optional oracle reference images. Test vectors never enter model fitting or alpha selection. Unique-image means from the training partition serve as concept prototypes and anchor references.

Image identities are grouped by SHA-256 of file contents, so repeated filenames and byte-identical aliases stay in one partition. Distinct encodings or near-duplicate pictures are not automatically merged. Test percentage applies to unique images per concept; validation percentage applies to the remaining unique images, with at least one image per concept in each partition. Trial averaging occurs after splitting and only within a single image identity; partial groups are retained. Training-only neural standardization precedes ridge regression. Alpha is selected from 1, 10, 100, 1000 and 10000 by validation image-vector MSE. When Target SVD is active ($k > 0$), regression fits the top $k$ principal target components and reconstructs to 768 dimensions. When Two-Stage Hybrid Decoding is selected (`clip_generation_hybrid`), Stage 1 predicts the concept prototype anchor using a linear class-balanced model, while Stage 2 predicts within-concept image residuals with joint $(\alpha, \beta)$ validation selection over residual weights $\beta \in [0, 1]$. This prevents regression shrinkage from collapsing predictions into an uninformative dataset mean. No L2 normalization is applied before generation. Cosine normalization is used only for retrieval metrics.

The results retain concept-retrieval metrics and additionally report exact-image top-1 retrieval against unique held-out images, within-concept image top-1 retrieval, image-vector MSE, and constant-training-target-mean MSE. Within-concept metrics exclude concepts with only one held-out candidate and report the number of evaluable predictions and their mean chance accuracy. Ties receive fractional top-1 credit and average rank. Retrieval metrics are averaged across test predictions; repeated test averages share a single gallery candidate. The Predictions table includes the stimulus filename, exact-image rank, within-concept rank and candidate count.

New bundles use profile schema version 2 (`individual_stimulus_image`) and save the exact test targets, image identities, averaging membership and training target mean. Version 1 concept-average bundles remain usable for generation/resume with their original targets and fingerprint. Existing models must be retrained to use image-specific targets; displaying them in a new layout does not change what they learned. Frozen image embeddings reuse the existing cache because the encoder and preprocessing are unchanged.

Generation uses seed 42, 30 steps and guidance 3, without text prompts. The safety checker remains enabled. Checkpoints are verified by SHA-256; incompatible vector profiles are rejected. Original image pixels are used for encoding targets and the comparison display, not fed to the diffusion stage for MEG generation.

The runtime defaults to `~/.cache/clip-image-test-venv/bin/python`; override with `CLIP_GENERATION_PYTHON`. It requires the prepared diffusers/transformers/torch environment and cached model revision `a2a13984e57db80adcc9e3f85d568dcccb9b29fc`. The app does not install packages or download checkpoints automatically. Generation runs offline in a separate process. The app's scientific environment is unchanged.

## All test predictions

Press **Generate all / resume…** to save one three-column comparison for every held-out average. All contributing input stimuli appear on the left, the MEG-generated prediction appears in the middle, and generation from `MEG prediction - block concept vector` appears on the right. Titles show `trial_index_in_file`, session and block for each contributing trial, plus the zero-based test-average index. The input images are displayed for reference; neither generated image receives the input pixels.

The block concept vector is the arithmetic mean of the raw projected CLIP image embeddings for `image_1`, `image_2`, and `image_3` in the matching `block_id` row of the nearest ancestor `block-instructions.csv`. If a test average contains trials from multiple blocks, their block vectors are averaged with one contribution per trial. The subtraction is literal in the 768-dimensional generator input space: no L2 normalization, projection, or norm restoration is applied. This makes the right panel an experimental ablation and may move the vector away from the generator's normal embedding distribution.

Outputs live beside the model in `images_all_comparisons`. `test_00000.png` is the combined comparison for test average 0. `predictions.csv` and `batch_manifest.json` include the contributing stimulus filenames, trial metadata, block IDs and labels, vector norms, residual-vector hash, and exact block-vector definition. Separate ideal images are no longer generated by the batch button. The original prediction pixels can be reused when upgrading a matching two-column comparison; the block-subtracted image still requires one new diffusion render.

**Stop images** stops after the current comparison; **Generate all / resume…** verifies and skips completed comparisons. Missing or corrupted comparisons are rebuilt. Changed predictions, metadata or input image contents cannot silently reuse the same batch folder. Missing input images fail before generation. **Open images folder** opens the comparisons folder.

New training bundles retain the original trial metadata. Older bundles can use an explicit `trial_metadata.csv` beside `inference_bundle.joblib`, with rows in the exact saved `stimuli` order and columns `stimulus`, `trial_index_in_file`, `session_id`, `block_id`, and `source_fif` or `source_fif_path`. Every stimulus row is checked before use. Without this metadata, within-file indices are labeled unavailable; global row positions are never presented as within-file indices. When no compatible model is in the current session, the app prompts for a trusted saved bundle.

This version does not support parcel batch searches or arbitrary existing embedding models. Single-example generation shows an ideal-image reference for version 2 bundles and the original ideal-concept reference for older bundles.

Generated images are exploratory visualizations, not proof of accurate decoding. New image-group splits exclude identical image files across partitions. Legacy version 1 models used trial splits and could share image identities. Individual CLIP targets retain more image-specific information but do not guarantee exact pose, color or shape reconstruction from MEG. Report held-out retrieval performance and avoid selecting attractive examples after viewing results.

Comparison titles also include the block type from the nearest ancestor `block-instructions.csv`, matching `block_id` to `line_2` (the same lookup applies to each session). The exact text is retained in each input trial’s `block_type` metadata. Generate all / resume refreshes changed block-type labels using the saved prediction pixels, without rerunning inference. Missing block instructions or unmatched block IDs do not produce guessed labels.
